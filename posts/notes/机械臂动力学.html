Pinocchio 动力学前馈：从重力补偿到链路验证

从机械臂静态保持偏软的问题出发，梳理反馈控制与前馈扭矩的职责，解释重力项、非线性项和 reduced model，并记录补偿链路的验证思路

发布于 2026-04-23

1. 引言 ​

在机械臂控制链路的调试过程中，一个很常见的问题是：

  • 机械臂能够跟随目标，但静态保持偏软；
  • 为了托住大关节，不得不持续提高 kpk_pkp​；
  • kpk_pkp​ 提高之后，系统虽然更“硬”，但柔顺性和可调性明显变差；
  • 引入动力学补偿后，如果链路没有真正打通，现象上又可能几乎没有变化

这类问题表面上看像是参数没有调好，但本质上往往涉及两个层面：

  1. 控制律中，误差反馈项是否承担了过多本不该由它承担的任务；
  2. 动力学模型是否真正和当前受控状态空间对齐，并且被正确用于前馈补偿

因此，这篇笔记记录以下几个问题：

  • 为什么机械臂控制中会需要动力学前馈；
  • g(q)g(q)g(q)、nle(q,q˙)\mathrm{nle}(q,\dot{q})nle(q,q˙​) 与完整逆动力学之间的区别；
  • reduced model 在工程实现中解决的是什么问题；
  • kp/kd/τffk_p / k_d / \tau_{\mathrm{ff}}kp​/kd​/τff​ 在当前控制律中的职责应该如何理解；
  • 如何判断补偿是“真正生效了”，而不是只是在主观感觉上似乎有所变化

2. 动力学解算与前馈补偿 ​

这里没有做完整的动力学解算，而是在以下流程中做的前馈补偿：

  • 上层控制器给出关节目标位置与目标速度；
  • 底层执行器负责闭环跟踪；
  • 中间引入一个由动力学模型计算得到的前馈扭矩项

它可以抽象成如下形式：

τ=Kp(qdes−q)+Kd(q˙des−q˙)+τffτ = K_p \left(q_{\mathrm{des}} - q\right) + K_d \left(\dot{q}_{\mathrm{des}} - \dot{q}\right) + \tau_{\mathrm{ff}} τ=Kp​(qdes​−q)+Kd​(q˙​des​−q˙​)+τff​

其中：

  • qdes,q˙desq_{\mathrm{des}}, \dot{q}_{\mathrm{des}}qdes​,q˙​des​：目标关节位置与目标关节速度；
  • q,q˙q, \dot{q}q,q˙​：当前真实关节位置与真实关节速度；
  • Kp,KdK_p, K_dKp​,Kd​：误差反馈项中的刚度与阻尼；
  • τff\tau_{\mathrm{ff}}τff​：由动力学模型给出的前馈项

因此，这里讲的动力学是指：

误差反馈控制 + 动力学前馈补偿

3. 为什么单纯依赖 kp/kdk_p / k_dkp​/kd​ 往往不够 ​

如果控制律中只有误差反馈项：

τ=Kp(qdes−q)+Kd(q˙des−q˙)τ = K_p \left(q_{\mathrm{des}} - q\right) + K_d \left(\dot{q}_{\mathrm{des}} - \dot{q}\right) τ=Kp​(qdes​−q)+Kd​(q˙​des​−q˙​)

那么系统要在某个姿态上“托住”机械臂，本质上只能依赖位置误差先建立起来，再由 KpK_pKp​ 产生恢复力矩

这会带来几个很典型的问题

3.1 保持能力依赖误差建立 ​

系统并不是“本来就能托住”，而是必须先偏一点，才能产生相应的纠正扭矩

典型现象通常包括：

  • 起步瞬间先轻微下垂；
  • 到达目标位姿附近仍显得偏软；
  • 某些大关节必须靠较大的误差才能维持住静态平衡

3.2 kpk_pkp​ 被迫承担了过多职责 ​

没有前馈补偿时，kpk_pkp​ 往往同时承担：

  • 位姿约束；
  • 重力抵消；
  • 外扰恢复

这会直接导致一个工程上的矛盾：

  • 想更稳，就需要提高 kpk_pkp​；
  • 想更柔顺，又必须降低 kpk_pkp​

如果“托住机械臂”这件事也完全交给 kpk_pkp​，那么刚度调节和静力补偿就被耦合到了一起

3.3 柔顺控制空间被压缩 ​

很多时候目标并不是“越硬越好”，而是希望系统呈现出一种更自然的状态：

  • 无外力干扰时能稳住；
  • 有外力干扰时又能适度被动跟随

这意味着 kpk_pkp​ 不能一味拉高；但只要没有前馈，大关节在低 kpk_pkp​ 下又往往托不住

因此，动力学前馈主要解决的是一个非常直接的问题：

把“托住机械臂”这件事，从纯误差反馈里拆出去一部分

4. 机器人动力学中的几个基本量 ​

在关节空间中，机械臂动力学常写成：

M(q)q¨+C(q,q˙)q˙+g(q)=τM(q)\ddot{q} + C(q,\dot{q})\dot{q} + g(q) = \tau M(q)q¨​+C(q,q˙​)q˙​+g(q)=τ

其中：

  • qqq：关节位置；
  • q˙\dot{q}q˙​：关节速度；
  • q¨\ddot{q}q¨​：关节加速度；
  • M(q)M(q)M(q)：质量矩阵；
  • C(q,q˙)q˙C(q,\dot{q})\dot{q}C(q,q˙​)q˙​：科氏项与离心项等速度相关非线性项；
  • g(q)g(q)g(q)：重力项；
  • τ\tauτ：关节广义力矩

这条式子是后续理解所有“补偿”与“前馈”的基础

4.1 重力项 g(q)g(q)g(q) ​

g(q)g(q)g(q) 只与当前姿态有关，与速度无关

它表示的是：

在当前姿态下，如果希望系统静态平衡，每个关节需要提供多少广义力矩来抵消重力

因此，g(q)g(q)g(q) 最适合首先用于：

  • 静态保持；
  • 低速轨迹跟踪；
  • 初步验证动力学模型方向与量级是否正确

4.2 非线性项 nle(q,q˙)\mathrm{nle}(q,\dot{q})nle(q,q˙​) ​

许多动力学库会直接提供：

nle(q,q˙)=C(q,q˙)q˙+g(q)\mathrm{nle}(q,\dot{q}) = C(q,\dot{q})\dot{q} + g(q) nle(q,q˙​)=C(q,q˙​)q˙​+g(q)

也就是把所有非线性项合并在一起输出

它相比单独的重力补偿，多考虑了速度相关项，因此更适合：

  • 速度较高的轨迹；
  • 加减速较明显的运动；
  • 需要改善动态跟踪品质的场景

4.3 完整逆动力学 ​

如果进一步考虑期望加速度 q¨des\ddot{q}_{\mathrm{des}}q¨​des​，则会接近：

τ=M(q)q¨des+C(q,q˙)q˙+g(q)τ = M(q)\ddot{q}_{\mathrm{des}} + C(q,\dot{q})\dot{q} + g(q) τ=M(q)q¨​des​+C(q,q˙​)q˙​+g(q)

这已经不再只是“补偿”，而是在做更完整的逆动力学求解

它与单纯的 g(q)g(q)g(q) 或 nle(q,q˙)\mathrm{nle}(q,\dot{q})nle(q,q˙​) 之间，差别不只是“多算了一项”，而是控制层级已经发生了变化

5. g(q)g(q)g(q) 与 nle(q,q˙)\mathrm{nle}(q,\dot{q})nle(q,q˙​) ​

从调试顺序上看，应该先验证 g(q)g(q)g(q) 是否可用，原因如下：

5.1 g(q)g(q)g(q) 更容易验证 ​

因为它只与姿态有关，所以当机械臂停在不同静态姿态时，前馈值应该随姿态变化，并且变化趋势通常更容易判断

例如：

  • 某些关节在抬臂时重力补偿应明显增大；
  • 某些关节在特定构型附近前馈应接近零；
  • 对称结构在某些姿态下会呈现较为直观的变化规律

5.2 nle(q,q˙)\mathrm{nle}(q,\dot{q})nle(q,q˙​) 更容易把问题混在一起 ​

一旦直接切到 nle(q,q˙)\mathrm{nle}(q,\dot{q})nle(q,q˙​)，现象里就会同时混入：

  • 速度反馈噪声；
  • 速度估计误差；
  • 动态模型不准；
  • 轨迹本身的速度与加减速特性；
  • 前馈项方向或量级错误

这样一来，即便现象“不对”，也很难快速判断到底是哪一环出了问题

5.3 合理的启用顺序 ​

因此，更稳妥的顺序通常是：

  1. 先验证模型链路能正常更新；
  2. 先只开 g(q)g(q)g(q)；
  3. 确认方向、量级和静态效果都基本合理；
  4. 再切换到 nle(q,q˙)\mathrm{nle}(q,\dot{q})nle(q,q˙​) 观察动态改善

6. reduced model ​

如果 URDF 中包含更多关节、联动关节、虚拟关节或仅用于显示/碰撞的附属关节，而控制器实际只管理其中一部分关节，那么直接使用完整模型就可能出现问题：

  • 模型维度与反馈状态维度不一致；
  • 某些关节没有实际控制输入，却仍然参与动力学求解；
  • 前馈输出与当前受控关节顺序不一致；
  • 更新函数看似执行，实际结果却不可信

6.1 什么是 reduced model ​

所谓 reduced model，并不是重新手工维护一份“简化版 URDF”，而是：

  1. 基于完整 URDF 建立 full model；
  2. 找出当前不参与控制的关节；
  3. 将这些关节锁定在参考位姿；
  4. 构造一个仅保留目标受控关节的 reduced model

6.2 reduced model 的意义 ​

它解决的不是“公式问题”，而是：

模型表达空间与控制状态空间对齐的问题

如果这一步不对，那么后续即便公式调用完全正确，得到的 g(q)g(q)g(q)、nle(q,q˙)\mathrm{nle}(q,\dot{q})nle(q,q˙​) 或 M(q)M(q)M(q) 也无法应用到实机上，因此，reduced model 本质上属于“先把接口语义对齐”的工作，而不是“控制优化”的工作

7. 从 URDF 到前馈量 ​

从实现链路看，动力学前馈通常经历以下几个步骤：

7.1 由 URDF 建立模型 ​

第一步是从机器人描述中建立刚体树、关节类型、惯量参数、质心位置和运动学拓扑关系

如果这一步的质量、惯量或质心本身就明显不合理，那么后续补偿即便“有反应”，也很可能方向不对、量级不对，或者只能在局部姿态下勉强有效

7.2 将当前关节状态映射到模型状态 ​

真实控制系统中的关节顺序，不一定和动力学库内部的模型顺序一致

因此工程里往往需要显式维护：

  • 外部控制器的关节顺序；
  • 模型内部的 qqq 索引；
  • 模型内部的 vvv 索引

这一步的本质不是简单拷贝数组，而是做一次“状态语义映射”

7.3 基于当前状态计算动力学量 ​

在完成状态映射后，常见的计算量包括：

  • g(q)g(q)g(q)：重力项；
  • nle(q,q˙)\mathrm{nle}(q,\dot{q})nle(q,q˙​)：非线性项；
  • M(q)M(q)M(q)：质量矩阵

其中：

  • g(q)g(q)g(q) 适合先用于静态补偿；
  • nle(q,q˙)\mathrm{nle}(q,\dot{q})nle(q,q˙​) 适合后续动态补偿；
  • M(q)M(q)M(q) 虽然不一定立刻用于控制律，但通常值得保留，因为后续逆动力学、操作空间控制和更细的阻抗设计都可能继续用到它

7.4 将前馈量叠加到执行器命令 ​

最后一步不是“打印出来”，而是必须真正进入控制命令

也就是说，系统最终发送给执行器的指令里，应当同时体现：

  • 目标位置；
  • 目标速度；
  • 前馈力矩

如果前馈值只在日志中存在，而没有实际叠加到底层命令，那么从执行器角度看，系统仍然等价于“没有补偿”

8. kp/kd/τffk_p / k_d / \tau_{\mathrm{ff}}kp​/kd​/τff​ 的职责 ​

在这一类控制律里，三者职责并不相同

8.1 τff\tau_{\mathrm{ff}}τff​ 负责“先托起来” ​

如果动力学模型基本可信，那么前馈项首先承担的是：

  • 抵消静力负载；
  • 抵消一部分已知非线性项；
  • 降低系统对纯误差反馈的依赖

也就是说，它不是用来“修正误差”的，而是用来提供一部分理论上本就该有的广义力

8.2 kpk_pkp​ 负责“有多硬” ​

在前馈存在时，kpk_pkp​ 的职责会更接近其本意：

  • 约束目标位姿；
  • 处理模型误差；
  • 在外扰后把系统拉回目标附近

如果没有前馈，kpk_pkp​ 还要额外承担静力补偿，于是就很容易被迫调大

8.3 kdk_dkd​ 负责“有多稳” ​

kdk_dkd​ 的主要作用仍然是阻尼：

  • 太低时，系统容易飘、回摆、发软；
  • 太高时，系统会显得拖滞、迟钝，甚至让运动过程不自然

因此，从职责分工来看，应该这么理解三个量：

  • τff\tau_{\mathrm{ff}}τff​：负责把系统托起来；
  • kpk_pkp​：负责刚度；
  • kdk_dkd​：负责阻尼

9. 如何判断补偿有没有真正生效 ​

9.1 先看数值有没有在变化 ​

最基础的检查方式是打印前馈值，观察它是否会随着姿态或速度变化而变化

如果出现以下现象：

  • 前馈值始终接近零；
  • 换了多个姿态仍几乎不变；
  • 数值方向明显与预期相反；
  • 打印值在变化，但执行器行为几乎没有任何差别；

那么首先应该怀疑链路本身，而不是先怀疑参数

9.2 做 A/B 对比，而不是只看单次体验 ​

更可靠的方法通常是：

  1. 关闭动力学补偿；
  2. 只开启 g(q)g(q)g(q)；
  3. 再切到 nle(q,q˙)\mathrm{nle}(q,\dot{q})nle(q,q˙​)；
  4. 保持同一组 kp/kdk_p / k_dkp​/kd​ 进行对比

重点观察：

  • 起步时是否更不容易先塌；
  • 中间姿态保持是否更稳；
  • 在相同 kpk_pkp​ 下是否更容易托住大关节；
  • 加减速过程是否更顺

9.3 “开关几乎没差别”通常优先排查什么 ​

如果动力学开关切换前后现象几乎无差别，优先排查以下几类问题：

  1. 模型维度是否与当前受控关节一致；
  2. 状态映射顺序是否正确；
  3. 更新函数是否真的成功执行；
  4. 前馈值是否真正进入底层控制命令；
  5. 质量、惯量、质心参数是否明显不准；
  6. 前馈量的物理语义是否与执行器扭矩接口一致

10. 调试顺序 ​

从工程实践看，动力学前馈的调试不宜一步到位，而更适合分层进行

10.1 第一轮：只验证模型链路 ​

目标不是“手感更好”，而是确认模型真的在更新

这一步主要检查：

  • 当前状态能否正确写入模型；
  • g(q)g(q)g(q) 是否会随姿态变化；
  • 输出维度与关节顺序是否正确；
  • 补偿值是否非零且量级合理

10.2 第二轮：只验证静态保持 ​

这一轮只关心一个问题：

重力补偿是否真的改善了保持能力

此时更适合把机械臂停在若干个非零中间姿态，对比有无补偿时的静态表现，而不是一开始就跑大动态轨迹

10.3 第三轮：再验证动态效果 ​

在确认 g(q)g(q)g(q) 基本可信后，再切换到 nle(q,q˙)\mathrm{nle}(q,\dot{q})nle(q,q˙​)，观察：

  • 中高速轨迹是否更顺；
  • 加减速阶段是否更自然；
  • 动态跟踪误差是否更容易控制

只有当前两轮都成立时，第三轮的结论才更可信

11. 总结 ​

动力学前馈的核心意义，并不只是“多算一个扭矩项”，而是重新划分控制律中各部分的职责：

  • 由前馈项承担一部分本就应由模型提供的广义力；
  • 由 kpk_pkp​ 更多负责刚度与位置约束；
  • 由 kdk_dkd​ 更多负责阻尼与稳定性

从实现角度看，真正决定补偿是否有效的，往往不是某一个公式，而是以下几件事是否同时成立：

  • 模型状态空间与控制状态空间是否对齐；
  • 当前关节状态是否被正确映射到动力学模型；
  • 前馈量是否被稳定计算出来；
  • 前馈量是否真正进入底层控制命令

因此，把动力学前馈接进控制链路，首先是一个“接口语义对齐”的问题，其次才是一个“控制性能优化”的问题，也就是先搞定配置才能进行控制算法的优化
