本附录将正文中的工作映射到不同运行架构，帮助确定计算、设备接入和数据交接的位置；具体算法、物理约定与验证方法沿用前三部分，矩阵中的分工表示所列范围下的常见实现

## 4.1.1. 架构与难度定义

| 架构 | 运行边界 |
| --- | --- |
| MCU 独立运行 | 一块或多块 MCU 与驱动器独立完成约定任务，开发端可用于建模、标定求解、训练和仿真，但不持续提供运行指令 |
| 主机直接控制 | Linux 等通用主机承担主要应用和控制计算，直接连接驱动器，不要求另设整臂 MCU 控制板，驱动器继续承担约定的内部闭环 |
| 主机与 MCU 协同 | 两者共同参与运行，按接口与实时预算分配感知、规划、轨迹和控制，不能只按算法名称划分 |

矩阵按固定构型、规模受控且具备浮点计算能力的 MCU，以及资源适配的主机进行教学分级；具体能力还需核对自由度、数据量、驱动接口、内存及最坏执行时间，所用硬件和任务范围改变后应重新判断

**低** 表示以成熟接口接入和配置为主，**中** 表示需完成算法实现与模块联调，**高** 表示存在显著的资源优化、复杂求解、实时性或跨节点集成工作；难度对应表内列明的实现范围，用于组织学习与实施工作，不代表任意硬件都能达到同样性能

部署位置应依据状态来源、命令含义、计算与通信时限确定；主机可以承担符合时序要求的反馈控制，MCU 也可以执行资源允许的模型、轨迹或推理，实际边界见附录二

## 4.1.2. 软件章节与运行分工

| 章节 | MCU 独立运行 | 主机直接控制 | 主机与 MCU 协同 |
| --- | --- | --- | --- |
| 第二部分第 1 节 开发基础与系统架构 | 中，裸机或 RTOS、静态资源与硬件适配 | 中，进程线程、库与设备适配 | 高，共享算法接口并管理跨节点职责 |
| 第二部分第 2 节 执行器接口与设备通信 | 中—高，本地总线与驱动状态，自研驱动另增难度 | 中—高，驱动库、总线主站与硬件接入 | 高，按设备接入位置验证主机与 MCU 通信、设备链路及状态映射 |
| 第二部分第 3 节 实时运行与故障管理 | 高，中断、任务、采样同步和本地停止 | 高，调度、内存、总线时序及负载隔离 | 高，分别确定关键周期、监控与失联动作，验证跨节点时序 |
| 第二部分第 4.1—4.3 节 运动学计算 | 中—高，固定模型、解析逆解或有限迭代逆解 | 中，通用模型及较复杂数值约束 | 中—高，主机可处理复杂求解，实时节点按需计算雅可比或局部逆解 |
| 第二部分第 4.4—4.5 节 几何与空间标定 | 中，零偏与低维求解；复杂求解放开发端，MCU 采样和应用 | 中—高，采样组织、批量求解与独立验证 | 中—高，采样节点提供同步数据，主机求解，运行节点应用参数 |
| 第二部分第 5.1—5.3 节 动力学计算 | 高，固定链递归计算和缓存，先验证周期预算 | 中—高，动力学库与模型扩展 | 高，主机建模校核，实时控制所在节点计算所需项 |
| 第二部分第 5.4—5.5 节 参数辨识 | 中—高，低维递推；批量整臂辨识通常放开发端 | 高，激励、数据处理、约束辨识和验证 | 高，控制节点执行受限激励并同步采样，主机求解与分析 |
| 第二部分第 6.1—6.2 节 状态与力估计 | 中—高，滤波、受限规模观测器和接触判断 | 中—高，融合、观测与同步处理 | 高，采样节点提供状态与时间，估计和融合按反馈来源及所需时限分配 |
| 第二部分第 6.3—6.5 节 视觉与场景 | 高，受图像规模和内存限制的处理或轻量推理 | 中—高，视觉、点云、重建与场景维护 | 高，通常由主机承担视觉与场景，其他节点提供同步状态和设备反馈 |
| 第二部分第 7 节 关节控制与动力学补偿 | 中—高，伺服、模型补偿，复杂优化另核算 | 中—高，周期控制及适配驱动，实时配置另验证 | 高，各反馈环路、补偿项和命令通道分别确定归属，按接口组成串级控制 |
| 第二部分第 8 节 任务空间与接触控制 | 高，局部任务、阻抗、导纳及力位控制需满足反馈和时限 | 高，任务空间、接触与视觉闭环 | 高，主机可提供视觉参考，MCU 可承担局部接触控制，分工按接口确定 |
| 第二部分第 9 节 轨迹生成与执行管理 | 中—高，插值、同步、状态到状态生成和本地执行 | 中，轨迹计算与控制器接入 | 高，比较目标、轨迹段和周期参考三种通信边界 |
| 第二部分第 10 节 路径规划与轨迹优化 | 高，简单场景搜索；复杂方案可离线求解，运行时检查适用条件 | 中—高，碰撞、采样规划、优化及动态重规划 | 高，通常主机规划，MCU 接收有效参考并反馈运动状态 |
| 第二部分第 11 节 操作技能与任务规划 | 中，固定技能与状态机；复杂任务方案可在开发端预先求解，运行时核对前提 | 中—高，技能、任务规划和执行监控 | 高，通常由主机决策，MCU 执行约定技能或动作并反馈可确认的结果 |
| 第二部分第 12 节 遥操作与示教数据 | 中，输入映射、数值记录，大规模多模态采集处理通常放开发端 | 中—高，多模态采集、映射与数据集处理 | 高，采样节点提供准确时间和执行反馈，主机对齐并存储 |
| 第二部分第 13 节 机器人学习与策略开发 | 高，适配小型推理；训练放开发端，先核对算子、资源与时延 | 中—高，按资源承担训练或推理，大模型可使用独立训练端 | 高，主机可承担推理与动作转换，MCU 按约定接收参考或叠加到指定基准的控制残差 |
| 第二部分第 14 节 仿真建模与算法验证 | 中—高，开发端仿真，MCU 按需参与 PIL 或 HIL | 中—高，仿真与系统联调在主机或开发端 | 高，在环测试按目标选择，增加跨节点通信、同步与失联验证 |
| 第二部分第 15 节 实机部署与运行维护 | 中—高，烧录、参数存储、调试接口与独立运行检查 | 中—高，安装、依赖、启动、资源和运行诊断 | 高，联合启动、参数匹配、故障定位和分层恢复 |

各反馈环路和补偿项分别具有明确归属，并不意味着系统只能存在一个闭环；例如上层外环与驱动器的速度、电流内环可以按接口组成串级控制，应核对输入输出语义、带宽和总作用，避免无意重复实现同一反馈或补偿；相关约定见第二部分第 1.3、2.2 节和第 7.1 节

标定包含采集、求解和应用，辨识包含激励、估计和验证，学习包含训练与推理；开发阶段连接电脑采集和分析，与部署后依赖电脑持续计算是不同条件，应分别说明

MCU 运行能力需按算法规模核验，矩阵、滤波和小型学习模型已有相应实现工具，但工具存在不代表任意规模模型都能满足控制周期[[cmsis]](https://arm-software.github.io/CMSIS-DSP/main/)[[tinyml]](https://developers.google.com/edge/litert/microcontrollers/overview)

外置智能相机或计算模块承担算法时，应计入整套系统的运行架构；如果任务依赖这些设备在线计算，就应如实标明其职责，不能仅因机械臂主控为 MCU 就将全部计算称为纯 MCU

## 4.1.3. 本体与外设章节的对应关系

| 章节 | 主要设计或学习工作 | 对运行架构的影响 |
| --- | --- | --- |
| 第一部分第 1 节 需求分析与机械臂构型 | 任务、自由度、工作空间与选型比较 | 决定模型规模和所需运动能力 |
| 第一部分第 2 节 机械结构与执行系统设计 | 结构、传动、平衡机构、执行器、反馈与电气 | 决定可用命令、反馈质量、供能条件和控制上限 |
| 第一部分第 3 节 几何基准与运动学模型 | 可复现基准、编码器映射与几何描述 | 各架构均需应用一致几何关系，MCU 可使用提取参数 |
| 第一部分第 4 节 质量属性与动力学模型 | 质量、质心、惯量与传动参数 | 按实际随动关系归属参数，各架构按控制需要加载模型或生成固定计算代码 |
| 第一部分第 5 节 制造装配与本体验证 | 实物测量、装配、精度与负载验证 | 测量结果反馈相关计算节点，处理器选择不能替代实物验证 |
| 第三部分第 1 节 外设架构与接口 | 设备边界、连接、模型归属与状态定义 | 区分随动附件、固定工位和辅助轴，各节点遵循相同动作及反馈语义 |
| 第三部分第 2 节 视觉设备 | 成像、安装、触发和标定条件 | 数据流配置、标定、光学坐标及成像时间需对应，数据规模决定接入资源 |
| 第三部分第 3 节 末端工具 | 机械、电气、固件、TCP 与载荷 | 局部控制可独立于整臂主控，实际换装与持物反馈决定参数更新和任务衔接 |
| 第三部分第 4 节 示教与采集设备 | 输入装置、校准与本地反馈 | 设备采样可在 MCU，映射和存储按规模分配，初始化状态与新操作事件分别处理 |
| 第三部分第 5 节 其他外接设备 | 测量、辅助轴和工位 | 测量有效性、运动关系、同步及资源占用影响控制与规划 |
| 第三部分第 6 节 外设联调与验证 | 独立设备到整体任务的验证 | 各架构均需检查空间、时间、动作结果与共享资源条件 |

## 4.1.4. 离线计算与在线应用

开发端结果应连同其物理含义、适用配置和使用方式交给运行端；运行端使用完整模型、提取参数或生成代码均可，但应在相同输入与配置下核对计算和应用结果

| 开发端工作 | 运行端使用 | 关键核对 |
| --- | --- | --- |
| CAD、URDF 与模型校核 | 完整模型，或参数表与计算代码，包含当前工具、载荷及已建模机械平衡作用 | 拓扑、坐标、单位、质量惯量与作用归属一致；配重按质量关系计入，弹簧等按相应力元处理，并对照计算结果 |
| 几何与手眼标定求解 | 关节映射、空间变换及其对应的安装和相机数据流配置 | 零位、变换方向、参数应用位置及图像处理状态匹配；用独立任务点检查完整坐标链 |
| 动力学辨识 | 用于补偿和观测的辨识结果，以及满足物理要求的仿真参数 | 区分可辨识基参数与逐连杆物理参数，按所用模型正确转换；核对机械平衡等作用归属、适用工况与独立预测误差 |
| 路径求解与轨迹优化 | 路点、轨迹段或本地目标，以及所需时间和边界条件 | 当前起始状态、环境、工具和载荷仍满足前提；后处理与接续改变条件时，重新核对相应约束 |
| 策略训练与模型压缩 | 权重、观测预处理、归一化统计、动作反变换及执行约定共同组成的推理配置 | 观测可用性、动作单位与参考状态、预测和执行时域一致；核对导出精度、推理时延及动作块衔接 |

模型中的重力与机械平衡归属沿用第二部分第 5.1 节和第 7.2 节，标定结果及实际数据流对应第三部分第 2.3 节；策略部署时按第二部分第 13.2、13.7 节核对从训练表示到设备命令的完整转换

更换工具、调整安装或更新模型后，应检查受影响的运行参数是否成套生效；结合第二部分第 15 节进行相应对照与维护，使离线计算正确、运行端应用正确和实机表现改善能够分别确认
